## 1. 总体架构设计

### 1.1 架构原则

本系统遵循以下架构原则：

- **微服务架构**：前后端分离，后端采用微服务设计，支持水平扩展
- **领域驱动设计(DDD)**：清晰的领域边界，分层的领域模型
- **高可用性**：核心组件采用高可用设计，故障自动切换
- **边缘计算**：边缘节点就近处理，降低网络延迟和带宽成本
- **云边协同**：中心服务与边缘节点协同工作
- **无状态设计**：后端服务无状态化，便于扩展和负载均衡

### 3.3 三层架构详细说明

#### 3.3.1 领域层(Domain Layer)

**职责**：封装核心业务逻辑，不依赖外部框架

**包含**：
- 领域模型(Entity, Value Object, Aggregate)
- 领域服务(Domain Service)
- 仓储接口(Repository Interface)
- 领域事件(Domain Event)

**约束**：
- 领域层不能依赖Spring或其他框架
- 领域模型必须是纯净的POJO
- 领域服务必须是无状态的
- 领域逻辑必须在领域层实现，禁止泄漏到应用层

#### 3.3.2 应用层(Application Layer)

**职责**：协调领域对象完成业务用例，事务控制

**包含**：
- 应用服务(Application Service)
- 命令对象(Command)
- 查询对象(Query)
- DTO(Data Transfer Object)

**约束**：
- 应用服务必须是事务的边界
- 应用服务不包含业务逻辑，只负责编排
- DTO必须与领域模型分离，禁止直接暴露领域模型

#### 3.3.3 基础设施层(Infrastructure Layer)

**职责**：提供技术实现，与外部系统交互

**包含**：
- 仓储实现(Repository Implementation)
- 数据库访问(JPA, MyBatis)
- 外部服务客户端(HTTP Client, Kafka Producer)
- 配置管理

**约束**：
- 仓储实现必须实现领域层定义的接口
- 禁止在仓储实现中包含业务逻辑
- 所有外部调用必须在基础设施层完成

## 4. 领域驱动设计

### 4.1 领域划分

根据业务特点，将系统划分为以下领域：

| 领域 | 聚合根 | 核心实体 | 领域服务 |
|------|--------|----------|----------|
| **用户域** | User | User, Role | UserDomainService |
| **摄像头域** | Camera | Camera, StreamSession | CameraDomainService |
| **边缘节点域** | EdgeNode | EdgeNode, NodeHealth | EdgeNodeDomainService |
| **区域域** | Region | Region | RegionDomainService |
| **视频流域** | StreamSession | StreamSession | StreamDomainService |
| **录像域** | Recording | Recording, RecordingFile | RecordingDomainService |
| **告警域** | Alert | Alert, AlertRule | AlertDomainService |

### 4.2 领域模型设计原则

#### 4.2.1 聚合(Aggregate)

**约束**：
- 每个聚合只有一个聚合根
- 聚合根负责保证聚合内部的一致性边界
- 聚合外部只能通过聚合根访问聚合内部
- 聚合之间通过ID引用，禁止对象引用

**示例**：
```java
// 摄像头聚合
@Entity
public class Camera {
    @Id
    private Long id;
    
    private String name;
    private CameraStatus status;
    private EdgeNodeId edgeNodeId;
    
    // 聚合内部实体
    @Embedded
    private CameraConnection connection;
    
    // 聚合根方法
    public void startStream(EdgeNode edgeNode) {
        // 业务逻辑
    }
    
    public void stopStream() {
        // 业务逻辑
    }
}
```

#### 4.2.2 值对象(Value Object)

**约束**：
- 值对象必须是不可变的
- 值对象没有唯一标识
- 值对象通过属性值判断相等性

**示例**：
```java
@Embeddable
public class CameraConnection {
    private String url;
    private String username;
    private String password;
    private ProtocolType protocol;
    
    // 无setter，通过构造器创建
}
```

#### 4.2.3 领域事件(Domain Event)

**约束**：
- 领域事件必须是不可变的
- 领域事件必须包含发生时间
- 领域事件必须包含聚合根ID
- 领域事件通过领域服务发布

**示例**：
```java
public class CameraOnlineEvent {
    private final Long cameraId;
    private final LocalDateTime eventTime;
    private final String edgeNodeId;
}
```

### 4.3 领域服务设计

**约束**：
- 领域服务必须是无状态的
- 领域服务不能依赖基础设施
- 领域服务可以访问多个聚合
- 领域服务的命名要体现业务意图

## 5. 核心模块设计

### 5.1 认证授权模块

#### 5.1.1 架构设计

```
┌─────────────┐
│  前端      │
└──────┬──────┘
       │ 1. 用户名密码登录
       ↓
┌─────────────┐
│ 认证服务    │ - Spring Security 6.2.4
│ - JWT Token │ - BCrypt密码加密
│ - RBAC      │ - Redis存储Token
└──────┬──────┘
       │ 2. 生成JWT Token
       ↓
┌─────────────┐
│  Redis      │ - Token存储
│             │ - 会话管理
└─────────────┘
```

#### 5.1.2 技术约束

| 约束项 | 约束内容 | 理由 |
|--------|----------|------|
| **认证方式** | 必须使用JWT Token | 无状态、跨域友好 |
| **密码加密** | 必须使用BCrypt | 单向加密、加盐、计算缓慢 |
| **Token存储** | 必须存储在Redis中 | 支持Token撤销、分布式会话 |
| **Token有效期** | 24小时 | 平衡安全性和用户体验 |
| **登录失败限制** | 5次失败锁定10分钟 | 防止暴力破解 |
| **权限模型** | 必须使用RBAC | 细粒度权限控制 |

#### 5.1.3 实现要点

1. **JWT Token生成**

#### 5.2.2 负载均衡策略

**约束**：
- 必须采用加权最小连接数算法(WLC)
- 必须考虑CPU使用率、内存使用率、地域因素
- 同一区域的摄像头优先分配到同一区域的边缘节点
- 节点负载超过80%时不接收新摄像头

**算法实现**：
```java
public class WeightedLeastConnectionsBalancer {
    
    public EdgeNode selectOptimalNode(Camera camera, List<EdgeNode> nodes) {
        // 计算每个节点的权重
        return nodes.stream()
            .filter(node -> node.isHealthy() && !node.isOverloaded())
            .max(Comparator.comparingDouble(this::calculateWeight))
            .orElseThrow(() -> new NoAvailableEdgeNodeException());
    }
    
    private double calculateWeight(EdgeNode node) {
        double loadWeight = 1.0 - (double) node.getCurrentConnections() / node.getMaxConnections();
        double cpuWeight = getCpuWeight(node.getCpuUsage());
        double memoryWeight = getMemoryWeight(node.getMemoryUsage());
        double regionWeight = getRegionWeight(node, camera);
        
        return loadWeight * cpuWeight * memoryWeight * regionWeight;
    }
}
```

- 必须使用Ingress对外暴露服务

#### 10.5.4 部署流程

**CI/CD流程**：

```
代码提交
    ↓
Git Push
    ↓
触发CI流水线
    ↓
┌──────────────────────────────────┐
│ 代码构建                        │
│ - 前端构建                     │
│ - 后端构建                     │
│ - 单元测试                     │
│ - 集成测试                     │
└──────────────────────────────────┘
    ↓
构建Docker镜像
    ↓
推送镜像到镜像仓库
    ↓
┌──────────────────────────────────┐
│ 更新K8s资源                   │
│ - 更新Deployment镜像版本       │
│ - 验证配置                    │
│ - 应用变更                    │
└──────────────────────────────────┘
    ↓
滚动更新(Rolling Update)
    ↓
健康检查
    ↓
部署完成
```

**技术约束**：
- 必须使用CI/CD流水线自动化部署
- 必须使用GitOps管理K8s资源
- 必须进行镜像扫描，发现安全漏洞
- 必须执行自动化测试
- 必须使用滚动更新策略
- 更新失败时必须自动回滚
