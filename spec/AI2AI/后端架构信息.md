# 后端架构信息

## 目录结构

```
backend/
├── aick-mmp-parent/           # Maven父项目配置
```

**关键实体**：

#### SystemApp（系统应用）
- 用于Edge节点等系统级认证
- 关联API密钥和边缘节点
- 包含权限集合（EDGE_REGISTER, EDGE_HEARTBEAT, EDGE_CONFIG_UPDATE）

#### ApiKey（API密钥）
- AK/SK认证的核心实体
- AK（Access Key）：标识符，以`ak_`开头
- SK（Secret Key）：加密存储，支持Redis缓存

**关键服务**：

#### 认证架构（工厂+策略模式）
- **UnifiedAuthFilter**: 统一认证过滤器，入口点
- **AuthenticationStrategyFactory**: 策略工厂，管理并按优先级调度策略
- **认证策略**:
  - `JwtAuthenticationStrategy` (优先级1): JWT认证
  - `AkskAuthenticationStrategy` (优先级2): AK/SK认证
  - `AnonymousAuthenticationStrategy` (优先级3): 匿名认证（后备）
- **认证流程**: 工厂按优先级尝试各策略，成功则设置SecurityContext，失败则继续下一个策略

#### EdgeNodeHealthService
- 定时检查边缘节点心跳
- 超时阈值：3分钟
- 自动标记离线节点
- **新增**: 标记OFFLINE后自动触发 `EdgeNodeFailoverService` 执行故障转移

#### EdgeNodeService / EdgeNodeServiceImpl（边缘节点服务）
- 边缘节点完整生命周期管理
- **区域关联**: 通过 `regionId` 关联区域系统，支持按区域查询
- **心跳处理**: 从心跳metrics中提取 `cpuUsage`、`memoryUsage`、`storageUsage` 等指标设置到实体字段，解决前端显示null问题
- **重启功能**: 实现真正的重启命令发送，通过HTTP请求调用边缘节点的重启接口
- **核心方法**:
  - `createEdgeNode()`: 创建边缘节点（支持 regionId）
  - `updateEdgeNode()`: 更新边缘节点（支持 regionId）
  - `deleteEdgeNode()`: 删除边缘节点
  - `getEdgeNodeById()`: 按ID查询
  - `getAllEdgeNodes()`: 分页查询所有节点
  - `findByRegionId()`: 按区域查询
  - `findByRegionIdIn()`: 按多个区域递归查询
  - `triggerFailover()`: 手动触发故障转移
  - `restartEdgeNodeService()`: 发送重启命令到边缘节点
  - `batchEnableEdgeNodes()`: 批量启用/禁用节点
  - `getNodeHealthDetails()`: 获取节点健康详情（含系统指标）

#### EdgeNodeFailoverService（新增）
- 边缘节点故障时的自动摄像头迁移服务
- 触发方式: 自动(AUTO, 节点离线) / 手动(MANUAL, API调用)
- 核心能力:
  - 查询源节点在线摄像头 → 分批选择最优目标节点(四因子权重+地域bonus) → 批量更新edgeNodeId → 失败的进入待分配池(PENDING_ALLOCATION)
  - 待分配池定期重试分配
- 并发控制: Semaphore + @Async异步线程池
- 配置项: `edge.failover.*` (enabled/mode/delaySeconds/batchSize/regionBonus等)

#### FailoverEventController（新增）
- 故障转移事件查询API (`GET /failover-events`)
- 支持按源节点/触发类型/状态筛选和分页

#### PendingAllocationScheduler（新增）
- 定时任务，按配置间隔处理待分配池中的摄像头
- 条件启用: `edge.failover.enabled=true`

#### CdnNodeService / CdnNodeServiceImpl（CDN节点服务）
- CDN节点完整生命周期管理
- **区域关联**: 通过 `regionId` 关联区域系统，支持按区域查询
- **负载均衡算法**:
  - 基础WLC（加权最小连接数）算法
  - 地理邻近性 + WLC 混合算法
- **核心方法**:
  - `createCdnNode()`: 创建CDN节点（支持 regionId）
  - `updateCdnNode()`: 更新CDN节点（支持 regionId）
  - `deleteCdnNode()`: 软删除CDN节点
  - `reportLoad()`: 负载上报
  - `getBestCdnNodesByWlc()`: WLC算法选择最佳节点
  - `getBestCdnNodesByGeoAndWlc()`: 地理+WLC混合算法
  - `testConnectivity()`: 连通性测试
  - `getCdnNodeStatistics()`: 节点统计信息
  - `findByRegionId()`: 按区域查询
  - `findByRegionIdIn()`: 按多个区域递归查询
- **健康检查**: 
  - 心跳超时检测（60秒阈值）
  - 定时连通性测试（每分钟）
  - 批量健康检查

#### CdnNodeHealthCheckTask（CDN节点健康检查定时任务）
- 心跳超时检查（每30秒）
- 节点连通性测试（每分钟）
- 节点运行状态统计（每5分钟）
- 过期负载历史数据清理（每天凌晨3点）

#### RegionService / RegionServiceImpl（区域管理服务）
- 区域树形结构管理
- 父子关系递归处理
- 区域移动（带循环检测）
- 递归删除（强制/软删除）
- 区域统计（摄像头数量、边缘节点数、CDN节点数等）
- **递归统计**: 支持统计该区域及所有子区域的节点数量（edgeNodeCount, cdnNodeCount）
- **直接统计**: 支持仅统计该区域本身的节点数量（directEdgeNodeCount, directCdnNodeCount）
- **边缘节点匹配优化**: 区域统计中边缘节点使用 `regionId` 直接匹配区域树，兼容旧数据使用 `location` 字段匹配

#### StreamingService / StreamingServiceImpl（流媒体服务）
- **Janus Gateway 集成**: 通过 WebSocket 与 Janus 通信，实现 RTSP → WebRTC 转码
- **核心方法**:
  - `startStream(Long cameraId)`: 启动流媒体会话
  - `stopStream(Long cameraId)`: 停止流媒体会话
  - `generateWebRtcOffer(Long cameraId)`: 生成 WebRTC SDP Offer
  - `processWebRtcAnswer(Long cameraId, String answer)`: 处理 SDP Answer
  - `getStreamRecordingUrl(Long cameraId, String startTime, String endTime)`: 查询录像回放 URL
  - `startStreamRecording(Long cameraId)`: 发送开始录像命令
  - `stopStreamRecording(Long cameraId)`: 发送停止录像命令

#### RecordingNotificationService（录像通知服务）
- 通过 Kafka 消息通知录像服务开始/停止录像
- **Kafka Topic**: `mmp-recording-commands`
- **支持命令**:
  - `START_RECORDING`: 开始录像
  - `STOP_RECORDING`: 停止录像
  - `QUERY_STATUS`: 查询录像状态
- **配置**: `notification.recording.*`

#### 录像存储模块（recording/）[新增]

**StorageProperties（存储配置）**:
- 本地存储根路径配置
- 录像保留天数（默认30天）
- 磁盘使用率阈值（默认80%）
- 清理后保留比例（默认70%）
- 下载并发限制（默认3个）
- 下载带宽限制（默认10MB/s）

**FileStorageService（文件存储服务）**:
- 获取录像文件路径
- 文件存在性检查
- MD5校验码计算
- 文件完整性验证
- 磁盘空间监控
- 文件删除操作

**RecordingDownloadService（下载服务）**:
- 并发控制（Semaphore，最多3个并发）
- 文件锁定（防止清理正在下载的文件）
- 下载状态追踪
- 批量下载准备

**RecordingCleanupService（清理服务）**:
- 定时清理任务（每天凌晨2点执行）
- 按保留天数清理过期录像
- 按磁盘使用率阈值自动清理
- 录像完整性验证

**API端点**:
- `GET /recordings/{id}/download` - 下载录像文件
- `GET /recordings/download/status` - 获取下载状态
- `POST /recordings/{id}/download/cancel` - 取消下载
- `POST /recordings/batch-download` - 批量下载准备

#### AlertNotificationService（告警通知服务）
- 支持多种通知渠道
- **WebSocket 通知**: 通过 STOMP 协议发送到 `/topic/alerts`
- **邮件通知**: 通过 Spring Mail 发送（需配置 `notification.email.*`）
- **短信通知**: 通过 HTTP API 调用短信网关（需配置 `notification.sms.*`）
- **Webhook 通知**: HTTP POST 到指定 URL（需配置 `notification.webhook.*`）

#### 通知渠道模块（channel/）
采用策略模式设计，支持多种通知渠道的灵活扩展：

- **NotificationChannel**: 通知渠道接口，定义统一的通知发送方法
- **NotificationChannelFactory**: 通知渠道工厂，自动注册并管理所有渠道实例
- **NotificationSenderService**: 通知发送服务，协调多渠道发送和处理重试逻辑
- **NotificationResult**: 通知发送结果，包含成功/失败状态、错误信息、重试标识

**已实现的通知渠道**：
- `EmailNotificationChannel`: 邮件通知，支持富文本邮件发送
- `SmsNotificationChannel`: 短信通知，支持多短信网关API
- `WebSocketNotificationChannel`: WebSocket应用内通知，支持全局广播和用户私有频道
- `WebhookNotificationChannel`: Webhook通知，支持签名验证和重试机制

**重试机制**：
- `NotificationRetryTask`: 定时任务，定期检查并重试发送失败的通知
- 支持可配置的最大重试次数和重试间隔
- 自动清理过期的发送日志

**通知发送日志**：
- `NotificationSendLog`: 记录每次发送的详细历史和重试信息

#### EscalationService / EscalationServiceImpl（告警升级服务）
告警升级机制，当告警未及时处理时自动升级通知：

**升级条件类型**：
- `TIME_UNACKED`: 未确认时长
- `TIME_UNRESOLVED`: 未解决时长
- `REPEAT_COUNT`: 重复次数
- `SEVERITY`: 严重程度升级

**升级动作类型**：
- `NOTIFY`: 发送升级通知
- `ASSIGN`: 分配给其他人
- `ESCALATE`: 继续升级
- `AUTO_RESOLVE`: 自动解决
- `CREATE_TICKET`: 创建工单
- `EXECUTE_WEBHOOK`: 执行Webhook

**定时检查**：
- `EscalationCheckTask`: 定时任务，每分钟检查需要升级的告警

#### AnalyticsService / AnalyticsServiceImpl（数据分析服务）
数据分析和统计服务，提供多维度数据分析：

**核心方法**：
- `getDeviceUsageStats()`: 设备使用率统计（在线率、故障率、MTBF、MTTR）
- `getBandwidthStats()`: 网络带宽统计（当前/平均/峰值带宽、流量）
- `getStorageStats()`: 存储容量统计（使用量、录像统计、趋势）
- `getAlertStats()`: 告警统计分析（级别分布、类型分布、趋势）
- `getAnalyticsData()`: 通用数据分析查询
- `getTrendData()`: 获取趋势数据
- `recordAnalyticsData()`: 记录分析数据
- `recordBatchAnalyticsData()`: 批量记录分析数据

**定时任务**：
- `AnalyticsCollectionTask`: 数据采集定时任务
  - 每分钟采集设备使用情况
  - 每5分钟采集带宽数据
  - 每小时采集存储数据

## 认证机制

### JWT认证
- 用于前端用户登录
- Token存储在Redis
- 通过`Authorization: Bearer <token>`传递

### AK/SK认证
- 用于Edge节点和系统间通信
- 通过HTTP头传递：`X-Access-Key`、`X-Signature`、`X-Timestamp`
- 签名格式：`HMAC-SHA256(METHOD + "\n" + PATH + "\n" + TIMESTAMP)`

### Edge节点认证流程
1. 超级管理员创建SystemApp
2. 为SystemApp创建ApiKey
3. Edge节点配置AK/SK
4. Edge节点发送请求时携带签名
5. Central验证签名并关联Edge节点
