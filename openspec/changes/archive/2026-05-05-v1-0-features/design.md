## Decisions

### 1. 区域管理数据结构
**决策：** 使用父子关系的递归树结构管理区域
**理由：** 树结构允许无限嵌套深度，支持拖拽重组，自然映射到分层地理组织（国家 > 省 > 市 > 站点 > 区域）。使用parent_id外键简单高效，便于查询。

**考虑的替代方案：**
- 物化路径（如 /1/2/3/）：子树查询更快但维护更复杂
- 嵌套集：范围查询高效但插入复杂
- 邻接表（已选择）：简单，满足大多数用例

### 2. CDN节点选择算法
**决策：** 地理邻近性 + 加权最小连接数（WLC）混合算法
**理由：** 纯WLC不考虑网络延迟，这对视频流至关重要。地理邻近性首先选择靠近边缘节点/摄像头的节点，然后WLC在选定节点间平衡负载。

**考虑的替代方案：**
- 轮询：简单但不考虑负载或延迟
- 纯WLC：不考虑地理距离
- 加权响应时间：实现复杂，需要额外监控

### 3. 告警规则评估引擎
**决策：** 基于规则的引擎，使用JSON模式进行条件聚合（AND/OR）
**理由：** 基于JSON的规则灵活、易于序列化、可存储在数据库中而无需复杂解析。支持复杂条件而无需代码更改。

**考虑的替代方案：**
- Drools（业务规则引擎）：对此用例过于复杂，增加复杂性
- 硬编码条件：不灵活，新规则需要代码更改

### 4. 告警通知渠道
**决策：** 邮件、短信和应用内WebSocket通知
**理由：** 多渠道确保告警无论用户当前在何种上下文中都能送达。WebSocket支持实时应用内告警而无需轮询。

### 5. 数据分析存储策略
**决策：** 按日聚合的时间序列数据 + 原始数据保留
**理由：** 指标（CPU、带宽、存储）天然是时间序列。按日聚合保留趋势同时减少存储。原始数据保留30天用于详细分析。

**考虑的替代方案：**
- 纯原始数据：存储无限增长，查询变慢
- 纯聚合数据：无法深入分析特定事件

### 6. 报表生成
**决策：** 使用Apache POI的服务端Excel导出
**理由：** 服务端生成不需要前端库，更好地处理大数据集，格式一致。

**考虑的替代方案：**
- 客户端导出（SheetJS）：大数据集受浏览器内存限制
- PDF导出：需求中未指定，Excel是商业数据的标准

## Risks / Trade-offs

**风险：** CDN节点同步可能导致节点故障期间视频中断
**缓解措施：** 实现带自动故障转移的健康检查。边缘节点在CDN节点不可用期间本地缓冲视频流。

**风险：** 告警规则评估可能影响系统性能
**缓解措施：** 使用Kafka消息队列进行异步评估。对具有相似条件的规则进行批量评估。

**权衡：** 无限深度的区域树可能使UI渲染复杂
**缓解措施：** UI限制为5层，后端无限制。对大树实现延迟加载。

**风险：** 数据分析查询可能因历史数据拖慢数据库
**缓解措施：** 按日期分区表，实施数据保留策略，在基于时间的列上使用索引。

**风险：** 告警通知传送失败（邮件/短信服务停机）
**缓解措施：** 使用指数退避重试，回退到应用内通知，记录传送失败用于监控。

## Migration Plan

**数据库迁移：**
1. 创建新表：`regions`、`cdn_nodes`、`alert_rules`、`alert_conditions`、`system_configs`、`analytics_data`
2. 添加外键约束和索引
3. 如需要，为现有摄像头回填默认区域
4. 在维护窗口部署以避免服务中断

**API迁移：**
1. 新端点位于 `/api/v1/regions`、`/api/v1/cdn-nodes`、`/api/v1/alert-rules`、`/api/v1/system-configs`、`/api/v1/analytics`
2. 现有端点不变（向后兼容）
3. 前端组件渐进式增强

**回滚策略：**
- 数据库更改使用可回滚的迁移
- API版本化允许通过配置禁用新功能
- 功能标志支持逐步推出
