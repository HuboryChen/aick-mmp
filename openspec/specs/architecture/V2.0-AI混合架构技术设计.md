## 0. 实现差异说明

> **本文档为 V2.0 初始设计稿。实际实现因工程优化和简化，与原始设计存在以下差异，以实际代码为准：**

| 条目 | 原始设计 | 实际实现 |
|------|----------|----------|
| AI 部署架构 | 混合 AI（边缘 AI + 云端 AI） | **集中式 AI**：所有分析在中央 GPU 服务器完成 |
| 帧传输 | Kafka 任务队列 + base64 嵌入 | **gRPC 流式传输**：Edge → AI Service 实时帧流 |
| 消息方向 | 双向：Central → AI / AI → Central | **单向**：AI Service → Central（3 Topic） |
| Kafka Topics | 5 个（ai-tasks, ai-cloud-results, ai-edge-results, ai-alerts, ai-metrics） | 3 个（ai-passenger-stats, ai-behavior-events, ai-vehicle-records）+ 1 DLQ |
| AI 服务架构 | 多服务拆分（Gateway + Passenger + Behavior + Analytics） | **单服务**：FastAPI 单体服务，内部模块化 |
| API 设计 | REST + WebSocket 实时推送 | REST 查询 + 前端 5s 轮询 |
| 帧分析接口 | POST /analyze/frame（multipart） | **gRPC 流**：HandleFrame(stream) |
| 热力图/预测 | 计划中（Phase 5） | **未实现**（范围缩减） |
| 边缘端 AI | 边缘节点运行 Python AI Agent + 车牌识别 | **边缘节点仅转发帧**，不运行任何 AI 推理 |
| 部署 | 多容器（ai-cloud-gateway, ai-passenger-service, ai-behavior-service, ai-edge-agent） | **单容器** ai-service |
| 数据库表 | 6 张表（含 config, blacklist, 热力图相关） | **4 张表**（ai_passenger_stats, ai_behavior_events, ai_vehicle_records, ai_vehicle_whitelist） |

## 1. 概述

### 1.1 背景

V2.0版本的核心目标是引入AI能力，实现智能运维分析。根据业务需求，本系统采用**集中式AI架构**：
- **边缘节点**：仅负责 RTSP 帧提取与转发
- **中央 AI 服务**：集中 GPU 推理，资源共享

### 1.2 设计原则

1. **实用性优先**：使用预训练模型，快速落地
2. **按需扩展**：GPU资源按业务负载弹性扩展
3. **统一接口**：边缘AI与云端AI提供一致的API接口
4. **平滑迁移**：不影响现有V1.0系统的稳定运行

## 4. 预训练模型方案

### 4.1 模型选型

| 分析任务 | 推荐模型 | 来源 | 精度 | 推理速度 |

### 4.2 模型下载与准备

```python
# models/download_models.py
from ultralytics import YOLO
import torch

def download_pretrained_models():
    """下载预训练模型"""
    
    # 人员检测模型
    yolo_person = YOLO('yolov8n.pt')  # COCO预训练
    yolo_person.export(format='onnx')
    
    # 车牌检测模型 (需要单独下载)
    yolo_plate = YOLO('yolov8n-plate.pt')  # 专用模型
    yolo_plate.export(format='onnx')
    
    # 导出为ONNX格式 (便于跨平台部署)
    print("Models downloaded and exported to ONNX format")

def optimize_for_edge():
    """边缘端模型优化"""
    # 使用ONNX Runtime进行优化
    from onnxruntime.transformers import optimizer
    
    optimized_model = optimizer.optimize_model(
        'yolov8n-person.onnx',
        model_type='yolov8',
        num_heads=4,
        hidden_size=256
    )
    optimized_model.save_model_to_file('yolov8n-person-opt.onnx')
```

```sql
-- AI分析配置表
CREATE TABLE ai_analysis_config (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    camera_id BIGINT NOT NULL,
    analysis_type VARCHAR(50) NOT NULL,  -- passenger, behavior, vehicle
    enabled BOOLEAN DEFAULT TRUE,
    config JSON,                          -- 分析参数配置
    roi JSON,                             -- 区域定义
    alert_threshold DECIMAL(3,2),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_camera_type (camera_id, analysis_type)
);

-- 客流统计数据表
CREATE TABLE passenger_statistics (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    camera_id BIGINT NOT NULL,
    stat_time TIMESTAMP NOT NULL,
    granularity VARCHAR(20) NOT NULL,     -- minute, hour, day
    in_count INT DEFAULT 0,
    out_count INT DEFAULT 0,
    peak_count INT DEFAULT 0,
    avg_dwell_time_seconds INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_camera_time (camera_id, stat_time, granularity),
    INDEX idx_stat_time (stat_time)
);

-- 行为告警记录表
CREATE TABLE behavior_alerts (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    alert_id VARCHAR(64) NOT NULL UNIQUE,
    camera_id BIGINT NOT NULL,
    alert_type VARCHAR(50) NOT NULL,       -- intrusion, loitering, fall, fighting
    severity VARCHAR(20) NOT NULL,         -- low, medium, high, critical
    confidence DECIMAL(3,2),
    start_time TIMESTAMP NOT NULL,
    end_time TIMESTAMP,
    duration_seconds INT,
    snapshot_url VARCHAR(512),
    video_clip_url VARCHAR(512),
    status VARCHAR(20) DEFAULT 'active',   -- active, acknowledged, resolved
    metadata JSON,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_camera_time (camera_id, start_time),
    INDEX idx_status (status),
    INDEX idx_type (alert_type)
);

-- 车牌识别记录表
CREATE TABLE vehicle_plates (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    camera_id BIGINT NOT NULL,
    plate_number VARCHAR(20) NOT NULL,
    plate_color VARCHAR(20),
    vehicle_color VARCHAR(20),
    confidence DECIMAL(3,2),
    list_status VARCHAR(20),              -- WHITELIST, BLACKLIST, NORMAL
    list_id BIGINT,
    capture_time TIMESTAMP NOT NULL,
    snapshot_url VARCHAR(512),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_plate (plate_number),
    INDEX idx_camera_time (camera_id, capture_time),
    INDEX idx_list_status (list_status)
);

-- 白名单管理表
CREATE TABLE vehicle_whitelist (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    vehicle_type VARCHAR(20),
    owner_name VARCHAR(100),
    valid_from DATE,
    valid_to DATE,
    status VARCHAR(20) DEFAULT 'active',   -- active, expired, revoked
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_plate (plate_number)
);

-- 黑名单管理表
CREATE TABLE vehicle_blacklist (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    plate_number VARCHAR(20) NOT NULL,
    reason VARCHAR(500),

    valid_from DATE,
    valid_to DATE,

    UNIQUE KEY uk_plate (plate_number)
```
